## Proposed bounded implementation

Ownership: deadline-cli/Sources/DataStore.swift, DeadlineCLI.swift, a narrowly named operation helper if needed, deadline-cli/Package.swift test registration, dedicated CLI/store tests, docs/BUILD-SESSION-STORAGE.md and reports/session-storage. Do not alter Models.swift wire shape, iOS UI/store, actual iCloud file, permissions or service configuration in this slice.

1. Add explicit selected-file storage, available consistently to all existing CLI commands. An explicit fixture path never falls back to default iCloud or legacy backups. Missing/malformed/unavailable selected files fail without creating empty data or replacing data from a backup. Keep default read compatibility; detect unavailable/dataless cloud metadata before contents access where supported. No automatic download. Mutation must refuse unavailable input.
2. One throwing transaction reads current data, validates and resolves exact target IDs, changes it, and atomically replaces it while holding the same local coordination boundary. Use NSFileCoordinator for existing Apple coordination and a stable sibling advisory lock for participating CLI processes; serialize the entire transaction, not only save. Catch validation failures before save. Document local participant scope; no claim of cross-device or stale-app snapshot safety.
3. Preserve existing commands and title convenience where uniquely resolvable, but resolve within transaction and return nonzero for absent/ambiguous targets. Expose project/deadline IDs for repeatable session work. Add exact-ID delete of a single selected subdeadline, with a read-only preview describing nested subtasks and a stale-content check for applying the approved removal. No implicit recurrence-series/project/template deletion. Preserve all unrelated records.
4. Add explicit approval acknowledgement for additions/removals at the CLI surface and documented session procedure; flag is an acknowledgement, not proof that a user actually consented. Reads/edits/complete retain ordinary access without extra approval. Edits can address title/date/completion by exact identity; deletion and addition must not be retried blindly. Prefer caller-supplied deadline UUID for idempotent add: same ID/same intended record readback is no duplicate; same ID/different fields fails. This uses the existing UUID model, no operation database.
5. Test actual isolated CLI commands, exact input/output/exit status, two writers, error/no-op byte preservation, reorder/missing/duplicate IDs, invalid dates, approval refusal, delete preview/stale apply, repeated add/remove, nested-subtask removal and unaffected recurrence siblings. Preserve meaningful red before production changes; independent reviews and Understudy/committed/canonical gates. No fresh-client/publication or live CRUD claim until separately exercised.

## Decision boundary before implementation

Recommended first delivery is complete session CRUD on explicit local selected data with bounded same-host concurrency, while default iCloud mutations stay unavailable until owner decides how stale app snapshots should be handled. CLI-only NSFileCoordinator does not solve that app behavior. Root should confirm whether to keep default writes held for this slice or extend ownership to the app's stale-write detection; the latter is a separate substantial app integration with UI error reporting and additional tests. Do not silently choose a new database or claim that filesystem locking solves iCloud conflicts.
